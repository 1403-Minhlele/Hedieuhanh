📘 CHƯƠNG 1: TỔNG QUAN & KIẾN TRÚC MÁY TÍNH 5 Chủ đề Trọng tâm
📌 1.1. Bản chất & Mục tiêu HĐH
▼
  • Định nghĩa:
    Cầu nối trung gian giữa phần cứng máy tính và người dùng. Không trực tiếp giải quyết bài toán người dùng.
  • Hai vai trò cốt lõi:
    • Resource Allocator: Quản lý và phân phối công bằng tài nguyên (CPU, RAM, I/O).
    • Control Program: Kiểm soát thực thi chương trình để ngăn lỗi và hành vi trái phép.
  • Mục tiêu:
    Thuận tiện (Convenience) cho người dùng + Hiệu quả (Efficiency) khai thác phần cứng.
  • Bootstrap Program: Bẫy đề thi
    Lưu trong ROM hoặc EEPROM (Firmware). Khởi tạo phần cứng → nạp OS Kernel vào RAM → chạy tiến trình đầu tiên.
⚡ 1.2. Cơ chế Ngắt (Interrupt)
▼
  • Ngắt phần cứng (Hardware Interrupt):
    Thiết bị ngoại vi (chuột, phím, ổ đĩa, Timer) gửi tín hiệu điện áp qua bus hệ thống tới CPU.
  • Ngắt phần mềm (Trap / Exception):
    Do lỗi lệnh (chia cho 0, truy xuất nhớ sai) hoặc do chương trình gọi System Call.
  • Véc-tơ ngắt (Interrupt Vector): Từ khóa
    Mảng bảng chỉ mục chứa sẵn các địa chỉ của các hàm phục vụ ngắt (ISR) tương ứng.
  • Quy trình xử lý:
    1. Lưu PC & Thanh ghi vào Stack → 2. Tra cứu ISR trong Interrupt Vector → 3. Chuyển Kernel mode chạy ISR → 4. Lệnh IRET khôi phục trạng thái cũ.
💾 1.3. Phân cấp Lưu trữ (Storage)
▼
  • 3 tiêu chí phân cấp: Kinh điển
    Tốc độ truy xuất | Chi phí trên bit | Tính bay hơi (Volatility).
  • Thứ tự tốc độ giảm dần:
    Registers > Cache (L1, L2, L3) > RAM > SSD/NVMe > HDD > Băng từ
  • Tính bay hơi:
    • Volatile (Mất khi cúp điện): Registers, Cache, RAM.
    • Non-volatile (Bền vững): SSD, HDD, Flash ROM, Băng từ.
🖥️ 1.4. Kiến trúc Hệ thống
▼
  • SMP vs AMP:
    SMP các CPU bình đẳng chia sẻ RAM; AMP phân cấp Chủ - Tớ (Master - Slave).
  • Gom cụm (Clustered):
    Nối qua LAN/SAN, chia sẻ chung ổ đĩa qua SAN, hướng tới Độ sẵn sàng cao (High Availability).
  • Phân tán (Distributed):
    Nối qua WAN/Internet, không chia sẻ bộ nhớ/ổ đĩa (Shared-Nothing), liên lạc bằng Message Passing.
🛡️ 1.5. Chế độ Hai Chế độ (Dual-Mode)
▼
  • Mode Bit: Bẫy điểm
    • Mode Bit = 1: User Mode (Chế độ người dùng).
    • Mode Bit = 0: Kernel Mode (Chế độ hạt nhân / Đặc quyền).
  • Lệnh đặc quyền (Privileged Instructions):
    Chỉ chạy ở Kernel Mode. Nếu User mode cố chạy → ném Exception ngay.
  • Bộ đếm Timer:
    Ngắt định kỳ chống chương trình chạy lặp vô tận, đảm bảo đa nhiệm công bằng.

⚙️ 2.1. Dịch vụ HĐH Cung cấp
▼
  • Giao diện:
    CLI (Dòng lệnh) và GUI (Đồ họa trực quan).
  • Thực thi & Quản lý I/O:
    Nạp mã vào RAM, cấp phát tài nguyên; che giấu phần cứng qua Device Drivers.
  • Quản lý File & An ninh:
    Tạo, xóa, ánh xạ file lên sectors đĩa; cô lập tiến trình và bảo vệ tài nguyên.
📞 2.2. Lời gọi Hệ thống (System Call)
▼
  • Định nghĩa:
    API trung gian cho phép chương trình người dùng yêu cầu dịch vụ của nhân Kernel.
  • Cơ chế:
    Kích hoạt ngắt mềm (Trap), chuyển Mode bit từ 1 (User) sang 0 (Kernel).
  • 3 Cách truyền tham số: Tự luận
    1. Thanh ghi CPU: Nhanh nhất nhưng số lượng bị giới hạn.
    2. Khối nhớ trong RAM: Lưu khối tham số vào RAM, truyền con trỏ qua 1 thanh ghi (Linux dùng).
    3. Ngăn xếp (Stack): Ứng dụng Push vào Stack, HĐH Pop ra.
🏗️ 2.3. Bốn Kiến trúc Nhân HĐH
▼
  • 1. Đơn khối (Monolithic):
    Tất cả dịch vụ gom trong Kernel space. Cực nhanh nhưng 1 lỗi nhỏ làm sập cả HĐH.
  • 2. Phân lớp (Layered):
    Chia N lớp. Lớp M chỉ gọi lớp M-1 ngay dưới nó. Tốc độ thấp do qua nhiều lớp.
  • 3. Vi nhân (Microkernel): Trọng tâm
    Kernel chỉ giữ IPC, lập lịch, bộ nhớ cơ bản. Đẩy Drivers, File System ra User space. Giao tiếp bằng Message Passing. Nhược điểm: Hiệu năng giảm do Context Switch liên tục.
  • 4. Hệ thống Lai (Hybrid):
    Kết hợp tốc độ Monolithic và tính mô-đun Microkernel (macOS Darwin, Windows NT/11).
🎯 2.4. Bẫy Thi Trắc Nghiệm Chương 2
▼
  • Bẫy Microkernel:
    Nhược điểm lớn nhất là suy giảm hiệu năng do chi phí truyền thông điệp và chuyển ngữ cảnh.
  • Bẫy Quản lý File vs Lưu trữ thứ cấp:
    Quản lý file là tạo/xóa/đọc/ghi file; Lưu trữ thứ cấp là cấp phát sector, quản lý khoảng trống đĩa.
